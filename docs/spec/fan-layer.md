# ТЗ: фан-слой — проявление, статистика, профиль

Слой, который превращает плеер в личный уголок фаната: приложение помнит, что ты слушал, и возвращает это обложками и цифрами. Живёт отдельно от плеера — вход с главного экрана.

Правила слоя:
- Никаких очков, уровней, XP и «достижений» с конфетти. Только предметные вещи: обложка, штамп, цифра, титул.
- Ничего не показываем, пока нечего показывать. Нет данных — нет плашки.
- Всё локально на старте (`localStorage`). Синхронизация — позже, по `initData`.
- Тон — как у самих релизов: сухо, по делу, без «Молодец!».

---

## 1. Проявление альбома

**Смысл:** обложка «проявляется» по мере того, как альбом осваивается. Пустой релиз — призрак, пройденный — полный цвет. Это единственная механика прогресса: изнашивания и выцветания нет.

**Правило прослушивания.** Трек считается прослушанным, если сыграно ≥ 80% длительности или сработал `ended`. Перемотка вперёд не считается. Повторное прослушивание счётчик не увеличивает.

**Формула.** `progress = listenedTracks / totalTracks`, округление до 0.01.

**Визуал (каталог, полка, страница артиста):**
- `0` — обложка обесцвечена (`grayscale(1)`, яркость 0.85), рамка пунктирная.
- `0 < p < 1` — цвет возвращается снизу вверх: поверх серой обложки лежит цветная копия, обрезанная по высоте `p`; насыщенность всего блока растёт `saturate(0.2 + 0.8p)`.
- `1` — полный цвет, сплошная рамка, штамп с номером релиза.
- Переход 420 мс, тот же токен `theme`.

**Где ещё видно:** страница релиза — под названием `4 из 11 треков` и тонкая полоска. Без кнопок и без «достижений».

**Исключения:** релиз из одного трека — та же логика `0/1` и `1/1`. Трек без LRC или без обложки прогресс не ломает.

## 2. Статистика

Считаем на устройстве, показываем в профиле.

| Метрика | Определение |
|---|---|
| `listenedTracks` | уникальных треков, прослушанных до конца |
| `totalMinutes` | суммарное время прослушивания, в минутах |
| `topRelease` | релиз с наибольшим временем прослушивания |
| `topTrack` | трек с наибольшим числом проигрываний |
| `replays` | сколько раз слушал топ-трек |
| `catalogShare` | `listenedTracks / всего треков каталога` |
| `nightShare` | доля прослушиваний между 23:00 и 06:00 |
| `lyricsShare` | доля сессий с открытым текстом |

Правила отображения:
- `totalMinutes` — целое, формат `1 240` минут; больше 600 — `20 ч 40 мин`.
- Если каталог меньше 10 треков — `catalogShare` не показываем.
- Все цифры — моно, `tabular-nums`.

## 3. Профиль

**Где живёт.** Не таб и не экран плеера. Вход — кнопка в шапке главного экрана (кружок 32 px с инициалом титула или монограммой), справа от метки каталога. Открывается полноэкранным шитом, закрывается кнопкой «назад»/свайпом.

**Что внутри:**
1. Титул — крупно, `display-l`.
2. Подпись под титулом — конкретика с цифрой: `ВДПС — 41% твоего времени`.
3. Абзац на 2–3 строки: короткая характеристика на основе данных (см. п. 4).
4. Три цифры: треков, минут, повторов.
5. Топ-релиз: обложка 64 px, название, доля времени, число прослушиваний, тонкая полоска.
6. Топ-трек: одна строка с числом повторов.
7. «Последнее» — 3 записи: трек и дата.
8. Кнопка «Поделиться карточкой» — карточка 1080×1350: обложка топ-релиза, титул, подпись, ник из Telegram, логотип.

**Чего не делаем:** сравнений с другими («ты слушаешь больше 87% фанатов»), лент, профилей других людей.

## 4. Титул и характеристика

**Правила выдачи.** Титул выбирается из таблицы по приоритету, первый подходящий побеждает. Пересчитывается раз в сутки, меняется не чаще раза в неделю (кроме первого получения).

| Титул | Условие |
|---|---|
| `РЕЗИДЕНТ` | топ-релиз ≥ 40% всего времени + прослушано ≥ 70% каталога |
| `НОЧНАЯ СМЕНА` | `nightShare ≥ 0.5` и ≥ 60 минут |
| `ДОСЛОВНЫЙ` | `lyricsShare ≥ 0.5` и ≥ 20 сессий |
| `НА ПОВТОРЕ` | `replays ≥ 15` у одного трека |
| `ДИГГЕР` | прослушано ≥ 10 релизов |
| `ПЕРВЫЙ РЯД` | прослушан весь каталог |
| `СЛУШАТЕЛЬ` | по умолчанию, от 10 прослушанных треков |

**Характеристика** — шаблон из данных, а не сочинение: `«{ТОП-РЕЛИЗ} — {ДОЛЯ}% твоего времени; {ЧАСЫ} часов ночью; «{ТОП-ТРЕК}» слушал {N} раз»`. Если данных на фразу не хватает — фраза не показывается.

## 5. Данные

```ts
type TrackStat = {
  listens: number        // прослушиваний до конца
  plays: number          // любых проигрываний
  lastAt: number         // timestamp
  maxPosition: number    // максимальная достигнутая позиция, сек
}
type ReleaseStat = { listenedTracks: number }
type ListenEvent = { trackId: string; releaseId: string; position: number; duration: number; at: number }

type FanState = {
  version: 1
  tracks: Record<string, TrackStat>
  releases: Record<string, ReleaseStat>
  totalSeconds: number
  sessions: { at: number; withLyrics: boolean }[]
  title: { id: string; since: number }
}
```

- Ключ хранилища: `kishlak:fan:v1`. Всё в одном объекте, чтобы не разъезжалось.
- Запись статистики — не чаще раза в 10 секунд, и всегда при `pause` / `ended` / уходе в фон (`visibilitychange`).
- `sessions` ограничить 500 последними записями (FIFO).
- Миграция по `version`; старые данные не теряем без нужды.
- На бэкенд позже уходит **агрегат**, не сырые события; `initData.user.id` как ключ.

## 6. Приёмка

- [ ] Прослушал 5 из 10 треков релиза → на обложке 50% заливки, сатурация между серым и цветом
- [ ] Перемотка на 90% и выход **не** добавляет трек в прослушанные
- [ ] Дослушал последний трек → штамп появляется с анимацией, тост «релиз собран»
- [ ] Повторное прослушивание не меняет визуал обложки
- [ ] `localStorage` очищен → приложение не падает, всё начинается заново
- [ ] Часы переведены на 23:30 → `nightShare` растёт, титул может смениться на «НОЧНАЯ СМЕНА»
- [ ] Титул не меняется чаще раза в неделю
- [ ] Профиль открывается с шапки главной, кнопка «назад» закрывает
- [ ] Карточка шаринга 1080×1350 не обрезает текст при длинном названии

## 7. Решено и открыто

Решено:
- Одна механика — проявление по доле прослушанных треков. Изнашивание убрано.
- Профиль — отдельный экран из шапки главной, не таб.
- Счётчик `12 / 28` в шапке каталога остаётся.
- Титул обновляется периодически: пересчёт раз в сутки, показ нового — не чаще раза в 7 дней, в профиле видна дата «с 12 ноября».
- Карточка шаринга — **после запуска**, идея сохранена (не выкидываем).

Открыто:
1. Титул — пересчитывается по привычкам или фиксируется навсегда как «эпоха»?
2. Нужен ли счётчик `12 / 28` в шапке каталога, если профиль уже показывает прогресс?
3. Карточку шаринга делаем в первой версии или после запуска?
