# Телеграм: бот и тестовая среда

Нужен ли бот прямо сейчас — и как проверять приложение на телефоне.

---

## Короткий ответ

| Этап | Бот нужен? |
|---|---|
| Задачи 01, 03, 04, 05, 06, 07 (весь интерфейс) | **Нет.** Разработка идёт в браузере: `npm run dev` |
| Задача 02 (фон, локскрин, Media Session) | **Да.** Без Телеграма это не проверить |
| Задача 08 (шаринг, deep links, Stars) | **Да** |
| Продакшн | **Да**, плюс домен с HTTPS |

То есть создавать бота сейчас не обязательно, но лучше сделать это один раз заранее — минут пять, и до задачи 02 он уже будет готов.

---

## Что даёт бот

Мини-приложение — это сайт, который Телеграм открывает в своём WebView. Бот нужен как «дверь»:

- кнопка меню чата (`web_app.url`) открывает приложение;
- deep links `t.me/<bot>?startapp=track_x` — для шаринга;
- платежи Stars;
- в перспективе — фолбэк «прислать трек файлом в чат».

Больше ничего бот не делает: сервер ему не нужен, вся музыка уже лежит статикой.

## Шаг 1 — создать бота

1. Открыть `@BotFather` в Телеграме.
2. `/newbot` → имя (например, `Кишлак Плеер`) → username (например, `kishlak_player_bot`).
3. Сохранить **токен** — он понадобится только если будем вызывать Bot API (например, отправлять треки в чат). В `.env`, не в git.

## Шаг 2 — включить Mini App

1. В `@BotFather`: `/newapp` → выбрать бота → название, описание, картинка 640×360.
2. После создания — задать URL: `/setmenubutton` → выбрать бота → отправить **HTTPS**-ссылку.
3. Проверить: в чате с ботом внизу появляется кнопка меню → открывает приложение.

Важно: Телеграм не открывает `http://` и `localhost`. Нужен HTTPS.

## Шаг 3 — HTTPS для локальной разработки

Пока приложение живёт на ноутбуке, его надо «выставить наружу» туннелем:

```bash
npm run dev            # в одном терминале, порт обычно 5173

# во втором — один из вариантов:
npx localtunnel --port 5173     # даст https://xxx.loca.lt
```

Лучше сразу cloudflared — без промежуточной страницы с IP и стабильнее:

```bash
npx cloudflared tunnel --url http://localhost:5173
```

Если `npx cloudflared` не ставится, скачать бинарник напрямую (Mac на Apple Silicon):

```bash
mkdir -p ~/bin
curl -L -o /tmp/cloudflared.tgz https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-darwin-arm64.tgz
tar -xzf /tmp/cloudflared.tgz -C ~/bin
~/bin/cloudflared tunnel --url http://localhost:5173
```

На выходе — строка вида `https://<случайные-слова>.trycloudflare.com`. Адрес живёт, пока открыт терминал, и меняется при перезапуске.

Ещё вариант — задеплоить на Cloudflare Pages или Vercel: постоянный HTTPS-адрес, его удобно держать в кнопке меню.

Обновляя кнопку меню: `/setmenubutton` каждый раз заново, либо через Bot API `setChatMenuButton`. После смены URL на iOS иногда нужно закрыть чат с ботом и открыть заново.

## Шаг 4 — проверка, что WebView живой

В консоли приложения выведи при старте:

```ts
window.Telegram?.WebApp?.initData ? 'tg: ok' : 'tg: браузер'
```

В браузере — `браузер`, в Телеграме — `ok`. Если в Телеграме `браузер`, значит страница открылась не как Mini App (обычно потому, что URL не HTTPS или кнопка меню ведёт не туда).

## Если не открывается

**`HTTP ERROR 408` или бескрайняя загрузка через туннель.** Почти всегда это Vite: он отдаёт 403 на запросы с чужим `Host` (домен туннеля), а localtunnel показывает это как 408. В `vite.config.ts` должно быть:

```ts
server: { host: true, allowedHosts: true },
```

Проверить, что это именно оно:

```bash
curl -o /dev/null -w '%{http_code}\n' -H 'Host: <твой-домен>.loca.lt' http://localhost:5173/
```

`403` — вот она, причина. `200` — Vite в порядке, смотреть дальше.

**Страница «You are about to visit…» с просьбой ввести IP** — защита localtunnel. Ввести IP, который она показывает, один раз в 7 дней на один IP.

**Пустая страница в Телеграме.** Проверить, что живы оба терминала: `npm run dev` и туннель. Адрес туннеля меняется при каждом перезапуске — тогда обновить его в меню-кнопке бота.

## Чего пока не делать

- **Не подключать Stars** — до задачи 08 и до юридической части это только путает.
- **Не покупать домен** — для тестов хватает туннеля, для продакшна потом решим.
- **Не хранить токен в репозитории** — `.env` уже в `.gitignore`.
- **Не делать бэкенд** — на этом этапе весь контент статический.
