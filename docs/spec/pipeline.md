# Пайплайн контента: от папки с треками до `release.json`

Что автоматизировано, что руками, и как это запускать.

---

## Один раз — поставить инструменты

```bash
cd ~/Desktop/kishlak-tg
/usr/bin/python3 -m venv tools/.venv
tools/.venv/bin/pip install mutagen imageio-ffmpeg pillow
```

- `mutagen` — теги и обложки из файлов;
- `imageio-ffmpeg` — свой ffmpeg, без Homebrew;
- `pillow` — ресайз обложек и расчёт палитры.

## Каждый релиз

Папка-источник: как скачалось, в любом виде. Имена файлов могут быть `01 Болею тобой.mp3`, `Болею тобой.wav`, `track_01.m4a` — не важно.

```bash
tools/.venv/bin/python tools/ingest.py ~/Downloads/ВДПС \
  --id vdps-2026 --title "ВДПС" --year 2026 --type album
```

Результат в `content/releases/vdps-2026/`:

```
cover.jpg         1400×1400, центр-кроп
cover-400.jpg     400×400 для сетки
release.json      палитра + треки
tracks/
  01-boleyu-toboy.mp3
  01-boleyu-toboy.lrc
  02-nochnaya-smena.mp3
  ...
```

Что делает скрипт:

| Шаг | Автоматически |
|---|---|
| Находит аудио | да, по расширениям, сортирует натурально (`2` раньше `10`) |
| Читает теги | да: название, артист, год, длительность |
| Достаёт обложку из файла | да (ID3 APIC, MP4 `covr`, FLAC pictures) |
| Конвертирует в MP3 320 | да, через встроенный ffmpeg; mp3 копируется как есть |
| Режет обложку в квадрат, делает 1400 и 400 | да |
| Считает полярность и акцент | да, по алгоритму из `system.md` |
| Подхватывает `.lrc` с тем же именем | да, нормализует имена |
| Переименовывает файлы в `01-slug` | да |
| Пишет `release.json` | да |
| Сообщает о проблемах | да: нет LRC, мало таймкодов, нет обложки |

Проверить без записи файлов: добавь `--dry-run`.

## Что остаётся руками

| Задача | Почему |
|---|---|
| Текст песни | у скрипта нет источника текстов |
| Таймкоды (LRC) | требует распознавания речи и правки — см. ниже |
| Обложка, если её нет в тегах | нужен оригинал от артиста или из официального релиза |
| Названия на «правильные» | если в тегах мусор — поправить `release.json` после генерации |
| Проверка на слух | скрипт не слышит, он считает |

## LRC: три пути

**A. Готовый `.lrc` от артиста или из релиза** — идеально, ничего не делаем.

**B. Есть текст + аудио → автосинхронизация.**
`stable-ts` / `WhisperX` слушают трек и расставляют таймкоды по строкам.
Честно: на обычном вокале точность высокая, на скриме и грязном миксе модель ошибается (мы это уже видели на треке 03 — Whisper не распознал вокал вообще). Автоматизация закрывает ~70%, правка обязательна.
Цена: модель ~1–1.5 ГБ, обработка трека минуты.

**C. Ручная разметка.** 20–40 минут на трек: играет музыка, ты нажимаешь пробел на каждой строке. Скучно, но результат точный и на 100% подконтрольный.

**План:** первые 3–4 трека делаем **C** (они же станут эталоном для вёрстки), параллельно пробуем **B** на одном, чтобы понять, стоит ли автоматизировать остальное.
Если пойдём в B — соберу локальную страницу-редактор: аудио + строки, пробел ставит таймкод, экспорт `.lrc`. Это ~100 строк и вечер работы.

## Чеклист перед тем, как отдавать контент в приложение

- [ ] обложка читается, не мыло, без чужих логотипов
- [ ] палитра адекватная: светлая обложка → `paper`, тёмная → `dark` (посмотреть глазами на `design/preview/flow.png` — там видно, как это работает)
- [ ] длительности в `release.json` совпадают с реальными (±1 с)
- [ ] у каждого трека либо есть `.lrc`, либо в плеере не будет превью текста
- [ ] первый таймкод попадает в вокал (±0.2 с)
- [ ] файлы прослушаны в приложении на iPhone и Android: играет, перематывает, фон не рвётся
