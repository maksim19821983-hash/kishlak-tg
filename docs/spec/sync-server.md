# Своя синхронизация: Cloudflare Worker + KV

Облако Телеграма (`CloudStorage`) в клиенте iOS не сохраняет данные между сеансами мини-аппа,
поэтому состояние живёт на нашем сервере.

## Что делает сервер

- `GET /` — вернуть состояние пользователя по подписи `initData`;
- `POST /` — сохранить состояние (до 100 КБ);
- авторизация: `x-init-data` проверяется HMAC-подписью токеном бота;
- хранение: KV, ключ `state:<telegram user id>`.

Клиент: `src/app/remoteSync.ts`, адрес берётся из `VITE_SYNC_URL` при сборке.

## Развёртывание (один раз)

```bash
cd ~/Desktop/kishlak-tg/server

# 1. создать namespace для данных
npx wrangler kv namespace create STATE
#    скопируй id в wrangler.toml → [[kv_namespaces]] id

# 2. положить токен бота секретом (он никогда не попадёт в клиент)
npx wrangler secret put BOT_TOKEN

# 3. опубликовать
npx wrangler deploy
#    в ответе будет адрес вида https://kishlak-sync.<аккаунт>.workers.dev
```

## Подключение клиента

```bash
cd ~/Desktop/kishlak-tg
VITE_SYNC_URL="https://kishlak-sync.<аккаунт>.workers.dev" npm run build
npx wrangler pages deploy dist --project-name kishlak-tg
```

После этого автосинхронизация идёт через сервер: при старте, при возврате в приложение,
раз в 90 секунд и через 2 секунды после прослушивания.

## Что выяснилось по дороге (не повторять)

- `CloudStorage` в клиенте iOS не сохраняет значения между сеансами мини-аппа: запись проходит,
  чтение в той же сессии работает, а после перезапуска ключи пусты. Поэтому от облака
  Телеграма отказались, остался только свой сервер и перенос кодом.
- Ключи `CloudStorage` не допускают точки (`STORAGE_KEY_INVALID`) — если когда-нибудь
  понадобится, только `[a-zA-Z0-9_-]`.
- `wrangler secret put` без аргумента-значения создаёт секрет из того, что ввели в приглашении;
  если вставить токен как имя секрета, токен попадёт в логи — перевыпускать через BotFather.

## Как проверить

Диагностика в приложении (долгое нажатие на «КИШЛАК») → блок «облако и перенос данных»:

- строка `server` — адрес воркера;
- кнопка «сервер: синхронизировать» → в плашке `сервер: избранное N, треков M`.


## Диагностика в приложении

В проде её нет: экран `/spike` и долгое нажатие на «КИШЛАК» включены только в dev-сборке
или при сборке с `VITE_DEBUG=1`.

```bash
# включить диагностику в собранной версии (для проверки на устройстве)
VITE_DEBUG=1 VITE_SYNC_URL="https://kishlak-sync.maksim19821983.workers.dev" npm run build
```

Перенос данных кодом (`src/app/transfer.ts`) остаётся в коде как аварийный путь,
но в обычной сборке кнопок для него нет.


## Вариант без отдельного домена: Pages Function

Если клиенты блокируют `*.workers.dev`, синхронизация живёт на том же домене:
`functions/api/sync.ts` → адрес `/api/sync`.

Требуется в панели Cloudflare → Workers & Pages → проект `kishlak-tg` → Settings:

1. **Functions → KV namespace bindings**: переменная `STATE` → namespace, созданный для воркера;
2. **Environment variables**: секрет `BOT_TOKEN` (тот же токен бота).

После сохранения настроек достаточно передеплоить сайт — клиент по умолчанию ходит на `/api/sync`.
