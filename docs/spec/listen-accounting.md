# Учёт прослушиваний: переписать с нуля

Решение принято после серии правок, которые не дали результата. Чинить дальше по частям бессмысленно: модель данных провоцирует ошибки.

## Что происходит сейчас

Симптомы с устройства:

- послушал **одну** песню из альбома — засчиталось **четыре**;
- прослушанное не отображается на обложках;
- после конца трека музыка иногда не переключается;
- каждая правка чинит одно и ломает другое.

## Почему так

1. **Счётчик `listenedTracks` хранится отдельно от фактов.** Он инкрементируется в `recordListen` рядом с `listens`, но живёт в другом поле состояния. Любая повторная запись или гонка даёт расхождение, которое уже не восстановить.
2. **Сессия прослушивания — глобальная переменная.** `sessionTrackId`, `sessionNaturalMax`, `sessionSeconds` общие на модуль. При смене трека, перезагрузке страницы, сворачивании или повторном монтировании слушателя они могут относиться к другому треку.
3. **Конец трека определяется тремя разными способами** (`ended`, `pause` у конца, таймер в RAF). У каждого свои условия срабатывания, они конфликтуют и дублируются.
4. **Кэш прогресса — вторая копия истины.** `_progressCache` пересобирается вручную; если её забыли пересобрать, UI показывает старое.

## Новая модель

### Принцип: никаких счётчиков, только факты

Храним **только** факты по каждому треку. Всё остальное выводится.

```ts
type TrackFact = {
  maxPosition: number   // максимальная натуральная позиция, сек
  duration: number      // длительность, сек (из аудио)
  seconds: number       // суммарно прослушано, сек
  plays: number         // запусков
  lastAt: number        // время последнего прослушивания
}

type FanState = {
  version: 3
  tracks: Record<string, TrackFact>   // ключ — trackId
  sessions: Session[]                 // журнал, максимум 500
}

type Session = {
  at: number
  trackId: string
  trackTitle: string
  releaseId: string
  seconds: number
  withLyrics: boolean
  completed: boolean
}
```

### Что считается прослушанным

```ts
const listened = fact.maxPosition / fact.duration >= 0.5 || fact.completed
```

- `completed` — трек реально дошёл до конца (одно из: `ended`, `pause` у конца, watchdog).
- Порог 50% по натуральному времени остаётся: на iOS воспроизведение часто не доходит до 100%.
- Перемотка вперёд не увеличивает `maxPosition`.

### Прогресс релиза — вычисляемый

```ts
function releaseProgress(releaseId: string, tracks: Track[]): number {
  const inRelease = tracks.filter((t) => t.releaseId === releaseId)
  if (inRelease.length === 0) return 0
  const listenedCount = inRelease.filter((t) => isListened(t)).length
  return listenedCount / inRelease.length
}
```

Никакого `rel.listenedTracks`. Счётчик релизов «собрано» — тоже вычисляемый: релиз собран, когда прослушаны все его треки.

### Сессия привязана к треку

Сессия живёт в объекте, а не в модульных переменных:

```ts
type LiveSession = {
  trackId: string
  releaseId: string
  duration: number
  naturalMax: number
  seconds: number
  startedAt: number
}
```

Правила:

- новая сессия создаётся **только** при смене `trackId` или старте с нуля;
- если пришло обновление для другого трека — старая сессия закрывается и пишется в факты, новая открывается;
- длительность берётся из аудиоэлемента, состояние — запасной вариант;
- обновление `naturalMax` — только когда `status === 'playing'` и дельта положительная и меньше 3 секунд.

### Единственная точка завершения трека

Один метод `finishTrack()` с защитой от повторного вызова на трек:

- вызывается из `ended`;
- вызывается из watchdog в кадровом цикле: `playing` и `currentTime >= duration - 0.4`;
- вызывается из `pause`, если позиция у конца;
- внутри: закрыть сессию, записать факты, пометить `completed`, перейти к следующему треку и запустить его.

Флаг «уже завершён» сбрасывается **только** при загрузке нового трека.

### UI без копий

- Прогресс, «любимое», «новое», счётчики профиля — всё считается из `FanState` функциями.
- Подписка одна: изменения `FanState` уведомляют UI через `subscribeFan`; никаких отдельных кэшей прогресса.
- Обложка: `progress` приходит из той же функции, что и список треков, — расхождение невозможно.

## Миграция

- Старый `kishlak:fan:v1` читается один раз: `tracks` переносятся как факты, `releases` **игнорируются** (они и были источником ошибок), `sessions` переносятся.
- Новый ключ — `kishlak:fan:v3`. Старый не удалять: если что-то пойдёт не так, есть откат.
- Запись: раз в 10 секунд при воспроизведении + принудительно на `pause`, `pagehide`, `beforeunload`, `visibilitychange`, смене трека.

## Тесты (обязательные до кода)

1. 10 секунд из 100 → не прослушано; 50 из 100 → прослушано.
2. Перемотка вперёд на 30 секунд не делает трек прослушанным.
3. Трек дошёл до конца → прослушан независимо от накопленного времени.
4. Смена трека в середине: факты пишутся первому, второму — нет.
5. Один трек прослушан дважды → `listens` не растёт, `plays` растёт.
6. Прослушал 1 трек из 4 → прогресс релиза ровно 25%, счётчик «собрано» = 0.
7. Перезагрузка страницы посреди трека → факты сохранились, прогресс на месте.
8. Битый JSON в localStorage → чистый старт без падения.
9. `finishTrack()` вызван дважды подряд → одна запись, один переход.
10. После последнего трека очередь зацикливается и продолжает играть.

## Критерий готовности

- На устройстве: слушаю трек до конца → в каталоге обложка альбома показывает ровно `1/N`, а не больше.
- Слушаю вторую песню → `2/N`.
- Перезагружаю страницу → цифры те же.
- После конца трека включается следующий, без нажатий.
