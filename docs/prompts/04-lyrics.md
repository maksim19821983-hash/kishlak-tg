# 04 — Текст и караоке

**Читай перед началом:** `CLAUDE.md` (раздел 5), `docs/design/screens.md` (раздел 3), `docs/design/system.md` (типографика).
**Результат:** работающий парсер LRC и экран караоке. Это вторая главная фича продукта.

## Задача 1 — парсер

`src/features/lyrics/parseLrc.ts` — чистый модуль, без DOM и React.

Поддержать:
- метаданные `[ti:]`, `[ar:]`, `[al:]`, `[by:]`;
- `[offset:±ms]` — сдвиг применяется ко всем строкам (положительный — раньше);
- таймкоды `[mm:ss.xx]` и `[mm:ss:xx]`;
- несколько таймкодов на одну строку `[00:12.00][00:45.10]текст` → две записи;
- word-level: `[00:12.00]<00:12.30>Слово <00:12.90>слово`;
- строки-паузы и инструментальные `♪` — не выбрасывать;
- CRLF, BOM, пустые строки, мусор в начале файла.

Выход:
```ts
interface LyricLine {
  time: number        // сек, с учётом offset
  text: string
  words?: { time: number; text: string }[]
  isBlank: boolean
}
interface Lyrics { meta: Record<string, string>; lines: LyricLine[] }
```
Строки сортируются по времени. Дубликаты по времени схлопываются в одну строку через `·`.

**Тесты (Vitest)** — обязательны, с фикстурами в `src/features/lyrics/__fixtures__/`: обычный файл, с offset, с word-level, с несколькими таймкодами, пустой, битый, с BOM.

## Задача 2 — поиск активной строки

`getActiveLineIndex(lines, currentTime)` — бинарный поиск последней строки с `time <= currentTime + 0.12`. Работает за O(log n), вызывается до 4 раз в секунду. Покрыть тестами: до первой строки, между строками, после последней, пустой массив.

## Задача 3 — экран караоке

`src/features/lyrics/LyricsView.tsx`:

- скролл-контейнер, строки рендерятся списком, **каждая строка мемоизирована** (`React.memo` по `isActive`, `isPast`, `text`) — при смене строки перерисовываются только две;
- активная строка позиционируется по центру экрана (offset 45%) через `transform: translateY(...)`, переход `lyric` 300 ms;
- верхняя и нижняя маски — градиент от `transparent` к `--bg-void`, чтобы текст «растворялся», а не обрезался;
- активная строка — `lyric-active` (Unbounded 600, 22, `--accent`);
- прошедшие строки — `--ink-mute`, будущие — `--ink-dim` (можно разницу в 10% непрозрачности);
- тап по строке → `seek(line.time)`, haptic `light`;
- word-level: если у строки есть `words`, активное слово получает `--ink`, прошедшие — `--accent`, будущие — приглушённые;
- `prefers-reduced-motion` → без плавной прокрутки, только мгновенная смена цвета.

Размещение: экран караоке — часть полного плеера (открывается пилюлей «Текст песни»), снизу — узкая волна и транспорт. Свайп вправо возвращает в плеер.

## Задача 4 — интеграция

- Если у трека нет LRC → пилюля «Текст песни» в плеере не рендерится вовсе (не `disabled`, а именно нет).
- Смена трека при открытом караоке: заголовок обновляется, текст скроллится к началу.
- Пауза: активная строка остаётся, прокрутка не дёргается.

## Ограничения

- Никаких внешних парсеров LRC.
- Никакого `scrollIntoView({behavior:'smooth'})` — он конфликтует с ручным скроллом пользователя; свой `translateY`.
- Если пользователь проскроллил вручную — автопрокрутка приостанавливается на 3 секунды, затем возвращается.

## Готово, когда

- [ ] Все тесты парсера зелёные, включая битые файлы
- [ ] Караоке прокручивается ровно, без прыжков на длинных треках (проверить на 5-минутном)
- [ ] Тап по строке перематывает трек точно
- [ ] Нет LRC → пилюли нет
- [ ] 60 fps в DevTools Performance при прогреве 30 секунд
- [ ] `reduced-motion` уважается
