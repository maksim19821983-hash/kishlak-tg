# 02 — Аудио и проверка фона

**Читать:** `CLAUDE.md`, раздел 4 и «Архитектурные границы».
**Результат:** работающее аудио за интерфейсом `AudioPort` и проверенный фон на живом телефоне.

Порядок: сначала код (спайк + движок), потом проверка. Проверка в Телеграме требует бота и HTTPS-туннеля — см. `docs/spec/telegram-setup.md`.

## Шаг 0 — страница спайка

Роут `/spike` (только dev):
- `<audio>` с реальным треком `/content/audio/vdps-2026/01-intro.mp3`, `preload="metadata"`, `playsInline`;
- кнопка play/pause, вывод `currentTime / duration` моно-шрифтом;
- `navigator.mediaSession`: `metadata` (title «Интро», artist «Кишлак», artwork 512 — обложка из `/content/covers/vdps-2026.jpg`);
- обработчики **обязательно все шесть**: `play`, `pause`, `previoustrack`, `nexttrack`, **`seekto`**, **`seekbackward`**, **`seekforward`**. В первом спайке `seekto` не было — из-за этого системный ползунок на локскрине мог не перематывать;
- в `seekto`: `audio.currentTime = details.seekTime`, затем сразу обновить `setPositionState` с новой позицией;
- кнопка «следующий» меняет метаданные на второй трек — так видно, обновляется ли локскрин;
- `setPositionState({duration, position, playbackRate})` — не чаще раза в секунду и **только** если `duration` конечное и больше нуля.

Этот шаг специально без движка: проверить механизм в чистом виде.

## Шаг 1 — проверка в браузере (1 минута)

`npm run dev` → `/spike` → play. Убедиться: играет, время идёт, метаданные в DevTools → Application → Media Session видны.

## Шаг 2 — проверка в Телеграме (нужен бот)

1. `npm run dev -- --host` (Vite станет доступен по локальной сети).
2. HTTPS-туннель на порт 5173: `npx localtunnel --port 5173` или `cloudflared tunnel --url http://localhost:5173`.
3. Ссылку вставить в кнопку меню бота (`/setmenubutton` в `@BotFather`).
4. Открыть на телефоне, зайти на `/spike`.

> **Результат спайка уже есть** (`docs/design/audio-findings.md`, 31.10.2026): на iPhone фон, локскрин и переключение треков с локскрина работают. Перемотка с локскрина работает, если зарегистрирован `seekto`. Гибридный фолбэк не нужен.

**Протокол (выполняет человек, результат — в `docs/design/audio-findings.md`):**
1. Открыть `/spike` в Телеграме на iPhone, нажать play.
2. Свернуть Телеграм — играет?
3. Заблокировать телефон — играет? Есть карточка с обложкой и названием?
4. Переключить трек с локскрина — метаданные обновились?
5. Вернуться в приложение — позиция совпадает с реальной?
6. Повторить на Android.

Файл `audio-findings.md`: модель телефона, версия Telegram, ответы по пунктам, вывод одной строкой: «фон работает через Media Session» / «не работает — нужен фолбэк». Если не работает — **не придумывать обходы**, зафиксировать и идти дальше.

## Шаг 3 — движок

`src/audio/port.ts` — интерфейс (уже создан заглушкой, привести к контракту):

```ts
export type PlaybackState = {
  status: 'idle' | 'loading' | 'buffering' | 'playing' | 'paused' | 'error'
  track: Track | null
  queue: Track[]
  index: number
  currentTime: number
  duration: number
  volume: number
  muted: boolean
  shuffle: boolean
  repeat: 'off' | 'all' | 'one'
  error: string | null
}
```

Методы: `load`, `play`, `pause`, `toggle`, `seek`, `next`, `prev`, `setShuffle`, `setRepeat`, `setVolume`, `subscribe`, `getState`, `dispose`.

`src/audio/webEngine.ts` — реализация на одном `HTMLAudioElement`:
- синглтон, живёт вне React, создаётся лениво;
- `audio.play()` возвращает промис — обрабатывать отказ (`NotAllowedError` → статус `paused`, без красной ошибки в консоли);
- смена трека сохраняет статус: играло — продолжает, стояло — грузит метаданные;
- `ended` → `next('ended')` с учётом `repeat`: `one` — тот же с нуля, `all` — по кругу, `off` — стоп на последнем;
- шаффл перемешивает очередь, сохраняя текущий трек на месте; выключение возвращает исходный порядок;
- **источник истины — `audio.currentTime`**: цифры и прогресс рисуются по нему через `requestAnimationFrame` во время игры; в стор `timeupdate` пишется с троттлингом 4 раза в секунду. Иначе интерфейс отстаёт (проверено на спайке);
- ошибка загрузки → `status: 'error'` и человеческий текст («трек недоступен»), а не URL.

`src/audio/queue.ts` — чистые функции `shuffleOrder`, `nextIndex`, `prevIndex`, `clampIndex` + тесты на все комбинации `repeat` × `shuffle` (включая очередь из одного трека и пустую).

`src/audio/mediaSession.ts` — метаданные и обработчики из шага 0, вынесенные в отдельный модуль; всё в `try/catch` (часть методов есть не во всех клиентах).

`src/audio/store.ts` — Zustand-стор поверх `AudioPort`; компоненты не трогают `<audio>` и не подписываются на сырые события.

`src/audio/background.ts` — заглушка `requestBackgroundFallback(track): Promise<boolean>` → `false`.

## Шаг 4 — связать спайк с движком

Кнопки на `/spike` перевести на `AudioPort`: play/pause/next/prev через стор. Плюс добавить **слайдер перемотки** (`<input type="range">`), который двигает `seek()`: тап — прыжок, перетаскивание — предпросмотр без дёрганья звука. Проверить, что перемотка работает и в браузере, и в Телеграме на телефоне.

Если это работает так же, как на голом `<audio>`, движок готов к UI.

## Ограничения

- Никаких плеер-библиотек.
- Никакого UI, кроме `/spike`.
- `play()` только по жесту пользователя.
- Один `visibilitychange` на документ, один `<audio>` на приложение.
- Не реализовывать фолбэк «отправить трек в чат» — только заглушка интерфейса.
