# 06 — Каталог: главная, артист, релизы, поиск, очередь

**Читай перед началом:** `docs/design/screens.md` (разделы 1, 4, 5, 6, 7, 8), `docs/design/system.md`.
**Результат:** все экраны, кроме плеера и караоке. Данные — из моков, бэкенда ещё нет.

## Задача 1 — слой данных

`src/data/catalog.ts`:
- `getArtist()`, `getReleases()`, `getRelease(id)`, `getTracks()`, `getPopular(limit)`, `getPlaylists()`, `searchCatalog(query)`;
- всё асинхронное (`Promise`), с искусственной задержкой 150–300 ms — чтобы состояния загрузки реально проверялись;
- типы: `Artist { id, name, aliases, bio?, plays?, releasesCount?, photo }`, `Release { id, title, year, type: 'album'|'ep'|'single', cover, trackIds }`, `Track { id, title, artistId, releaseId, duration, cover, audioUrl, lrcUrl?, palette? }`;
- счётчики (`plays`) — **опциональные**: если нет, в интерфейсе не показываем ничего, а не «0».

## Задача 2 — главная

По вайрфрейму. Детали:
- Hero: обложка играющего трека (если играет), иначе последнего релиза; высота 56vh, `object-position: center 20%`.
- Секции: «Новое» (карусель релизов), «Популярное» (5 строк), «Плейлисты» (горизонтальная карусель).
- Карусель: `overflow-x: auto`, `scroll-snap-type: x mandatory`, `scrollbar-width: none`, правый край обрезан на 20 px.
- Заголовки секций — `SectionHeader` (моно-метка + «все»).
- Свайп вверх по hero или тап по волне → открыть полный плеер / перемотка.

## Задача 3 — артист

- Плакат 62vh, обложка `object-fit: cover`, затемнение снизу в `--bg-void`, имя — `display-xl` поверх плаката.
- Счётчики — `mono`, только если есть данные.
- Кнопка «Слушать» — белая, 56 px высотой, с глифом play.
- «Популярное» — 5 треков, затем «Релизы» и «Синглы и EP» (разделение по `type`).
- Параллакс плаката при скролле — максимум 40 px, `transform` only, отключается при `reduced-motion`.

## Задача 4 — релиз

- Обложка 300×300 по центру, за ней — размытая копия (та же, что в `SceneBackdrop`, но локально в блоке).
- Список треков с номерами (`String(i+1).padStart(2,'0')`, моно).
- Играющий трек: акцентная полоска 2×16 слева, номер и название — в акценте.
- Длительность трека — `mono`, справа.

## Задача 5 — любимые

- Лайкнутые треки (Zustand + `localStorage`), счётчик в заголовке.
- Плейлисты: создание (имя), добавление, удаление. Хранение — тоже локально.
- Пустое состояние — по тексту из `screens.md`.

## Задача 6 — поиск

- Поле 48 px, автофокус при открытии таба, кнопка очистки.
- Фильтры-пилюли: Все / Треки / Релизы.
- Дебаунс 150 ms, поиск по названию трека, релиза и алиасам артиста, без учёта регистра и раскладки (`ё`→`е`).
- Недавние запросы — 5 штук в `localStorage`.
- Пустой результат — фраза из `screens.md` (с характером, без «упс»).

## Задача 7 — очередь (шит)

- Секции «Сейчас» и «Дальше», тап по треку — играть, свайп влево — убрать.
- «Очистить» — оставляет текущий трек и следующий за ним.
- Перетаскивание — не делать, оставить `TODO` в backlog.

## Задача 8 — навигация

- Табы: Главная / Любимые / Поиск. Состояние табов и вложенных экранов — в памяти (без URL-роутинга, но с сохранением при переоткрытии мини-аппа через `sessionStorage`).
- Вложенные экраны (артист, релиз, очередь) — `BackButton` Телеграма.
- Переходы: сдвиг + `opacity`, 200 ms, без «поехавших» углов.

## Ограничения

- Никаких таблиц, виртуализации и бесконечной подгрузки — каталог маленький.
- Никаких скелетонов «на всякий случай»: скелетон только там, где реально ждём данные.
- Не менять дизайн-систему под удобство вёрстки.

## Готово, когда

- [ ] Все 6 экранов кликаются, навигация не теряет состояние плеера
- [ ] Каждый экран имеет состояния: загрузка / пусто / ошибка
- [ ] Длинные названия и отсутствие обложки не ломают сетку
- [ ] `BackButton` работает на вложенных экранах и не виден на главной
- [ ] Скролл 60 fps на iPhone и Android
- [ ] Тёмная тема без белых вспышек при переходах
