# Промты: как пользоваться

Промты переписаны под актуальный дизайн: бумага/чернота, кассета, вкладыш, лента, фан-слой.
Актуальная основа — `docs/design/system.md` и `docs/design/screens.md`.

Каждый файл — самостоятельная задача для Claude Code. Отправляй **по одному**, по порядку, и не переходи к следующей, пока предыдущая не прошла приёмку.

## Порядок

| # | Файл | Что получаем на выходе |
|---|---|---|
| 01 | `01-scaffold.md` | Каркас: токены, полярность, шрифты, роуты, моки |
| 02 | `02-audio-engine.md` | `AudioPort`, движок, проверка фона и локскрина |
| 03 | `03-polarity.md` | Бумага/чернота из обложки + акцент |
| 04 | `04-catalog.md` | Сетка принтов и кадр релиза |
| 05 | `05-cassette.md` | Кассета-плеер и лента мини-плеера |
| 06 | `06-insert.md` | Парсер LRC и вкладыш |
| 07 | `07-fan-layer.md` | Проявление, статистика, титул, профиль |
| 08 | `08-telegram.md` | Шаринг, deep links, Stars, полировка |

Порядок не случайный: **02** идёт вторым, потому что фон — единственный технический риск. Если он не работает, вся остальная работа может потребовать гибридной схемы.

## Как формулировать свой промт

```
Задача: <что сделать, одной фразой>
Контекст: <какие файлы/экраны это затрагивает>
Сделать: 1) ... 2) ... 3) ...
Не делать: <что не трогать>
Готово, когда: <проверяемый чеклист>
```

## Правила

- Одна задача — один коммит: `git commit -m "<фаза>: <что сделано>"`.
- Claude обязан начать с `CLAUDE.md`. Если не делает — вставь первой строкой: «Сначала прочитай CLAUDE.md, docs/MAP.md, docs/design/system.md и docs/design/screens.md».
- Если ответ начинается с «я решил сделать иначе» — не принимай, попроси следовать спеке. Спека обсуждается с тобой, а не с ним.
- В конце каждой задачи — отчёт: что сделано, что проверено, где риски. Без отчёта задача не закрыта.
- Скриншоты макетов для сверки: `design/preview/*.png`, живые макеты — `design/sheet-*.html`.
