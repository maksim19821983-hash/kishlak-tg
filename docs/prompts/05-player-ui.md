# 05 — Плеер и мини-плеер

**Читай перед началом:** `docs/design/screens.md` (разделы 2 и «Сквозные правила»), `docs/design/system.md`.
**Результат:** полный плеер и мини-плеер. Это лицо продукта — здесь нельзя «примерно».

## Задача 1 — волна (`src/features/player/WaveSeek.tsx`)

- 64 столбика, ширина 2 px, шаг 3 px, высота 4–28 px, скругление 1 px.
- Высоты детерминированы от `track.id` (хэш → псевдослучайная последовательность), **не** от `Math.random()` на каждый рендер. Если в данных есть реальные пики — берём их.
- Сыгранная часть — `--accent`, остаток — `--ink-mute` с прозрачностью 0.45.
- Перетаскивание: `pointerdown` → `pointermove` → `pointerup`. Пока тащим — показываем время над пальцем (пилюля, mono 12), аудио не трогаем; после отпускания — `seek`.
- Тап (без движения) — мгновенный `seek`.
- Внешний вид не меняется при буферизации; буферизация показывается на кнопке play.

## Задача 2 — транспорт (`Transport.tsx`)

- Кнопки: шаффл, prev, play/pause (72×72, белая плашка, чёрный глиф), next, repeat.
- Боковые кнопки — 44×44, `--ink-dim`, активное состояние (шаффл/репит) — `--accent`.
- Буферизация: вместо глифа в кнопке play — кольцо прогресса (SVG, 2 px, акцент), без спиннеров.
- Нажатие play/pause — haptic `medium`. Переключение трека — `light`.
- На границах очереди (`repeat: off`, первый/последний трек) кнопки prev/next полупрозрачны, но остаются нажимаемыми — при нажатии haptic `warning` и ничего не происходит.

## Задача 3 — полный плеер (`src/features/player/FullPlayer.tsx`)

Строго по вайрфрейму из `screens.md`:

- обложка 1:1, ширина экрана минус 40 px, скругление 16, hairline;
- название — `display-l`, 2 строки максимум, `-webkit-line-clamp: 2`;
- артист — `body`, `--ink-dim`;
- волна + таймкоды (`0:42` слева, `−1:38` справа, моно, tabular);
- пилюля «Текст песни» (если есть LRC);
- транспорт;
- нижний ряд: лайк, «в плейлист», «скачать» (пока `disabled` с тултипом «скоро»), «меню» (шит-заглушка).
- Верхняя панель: шеврон вниз (закрыть) и «⋯».
- Открывается как шит снизу поверх текущего экрана, закрывается свайпом вниз (порог 120 px или скорость > 0.5 px/ms) и по кнопке.
- Кнопка «назад» Телеграма закрывает плеер.

## Задача 4 — мини-плеер (`src/features/player/MiniPlayer.tsx`)

- 64 px, `--bg-raised`, обложка 40×40, название (1 строка, 13 px), артист (mono 11, dim), play/pause 40×40.
- Прогресс — hairline 2 px по нижней кромке, акцент, без анимации `width` (использовать `transform: scaleX`, чтобы не было перерисовки).
- Нет трека — компонент не рендерится.
- Тап по плееру (кроме кнопки play) открывает полный плеер.
- Появление/скрытие — `translateY` + `opacity`, 200 ms.

## Задача 5 — жесты и связка

- Свайп вверх по мини-плееру — открыть полный.
- В полном плеере: свайп влево → караоке (если есть, иначе ничего), свайп вправо → очередь, свайп вниз → закрыть.
- Все жесты — на `pointer`-событиях, не на `touch`, и не мешают вертикальному скроллу экранов.
- `prefers-reduced-motion` — шит открывается без анимации.

## Ограничения

- Никаких анимационных библиотек, только CSS и `transform`.
- Нельзя вешать `timeupdate`-подписку на компоненты: только на стор, точечными селекторами.
- Никаких хардкод-цветов, только токены.

## Готово, когда

- [ ] Волна перематывает точно, время под пальцем совпадает с реальной позицией после отпускания
- [ ] Мини-плеер не дёргается при скролле экрана (проверить на главной)
- [ ] Открытие/закрытие полного плеера — 60 fps
- [ ] Все состояния кнопки play: idle / playing / buffering / error
- [ ] Длинные названия (40+ символов) не ломают вёрстку в мини-плеере
- [ ] Смена трека не мигает обложкой (кроссфейд из задачи 03)
- [ ] Работает на Android (там жесты и `safe-area` ведут себя иначе)
