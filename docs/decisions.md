## 2026-10-31 — Фаза 0: каркас

**1. Токены акцента: `--accent` и `--accent-text`.**

В задаче 01 упоминались `--accent-ink` и `--accent-wash` (из ранней версии дизайна). Правильно — как в `system.md`:
- `--accent` — линии, прогресс, фон штампа;
- `--accent-text` — текст, подогнанный до контраста 4.5:1.

Причина: сырой цвет обложки («ВДПС» даёт `#64A4B4`) на бумаге имеет 2.27:1 и для текста не годится.
Статус: **принято**, задачи 01 и 03 поправлены.

**2. Роутер: свой, на History API (~50 строк), вместо react-router.**

Пакеты добавляем только с согласования. Шесть экранов и один параметр (`release/:id`) библиотеки не требуют.
Условия, при которых пересмотрим:
- роутер вырастает больше ~150 строк;
- появляются вложенные маршруты или восстановление стека после перезагрузки;
- нужен deep-link на вложенные экраны (пока хватает `?startapp=`).

Статус: **принято**. Тесты на `parse`/`href` есть. Интеграция с `BackButton` — в задаче 04.

**3. Коммит фазы 0 содержит только код.**

## 2026-10-31 — Тест через туннель: белый экран

**Причина 1. localtunnel отдаёт `408` на часть запросов.** Один и тот же `/src/main.tsx` в трёх попытках подряд вернул `408`, `200`, `200`. Если модуль не загрузился — React не монтируется, экран остаётся белым.
Статус: для проверок на телефоне используем `npx cloudflared tunnel --url http://localhost:5173` (без промежуточной страницы и стабильнее).

**Причина 2. `telegram-web-app.js` грузился блокирующим `<script>` из `index.html`.** Если telegram.org недоступен (в РФ бывает), парсинг и монтирование висят.
Исправлено: скрипт удалён из `index.html`, SDK грузится лениво в `src/app/telegram.ts` (`ensureSdk()`, `async`, таймаут 3 с, ошибка не фатальна). Приложение рендерится независимо от доступности telegram.org.
Статус: **принято**. Это же поведение защищает реальных пользователей в РФ.

**Также:** в `vite.config.ts` добавлено `server: { host: true, allowedHosts: true }` — без этого Vite отдавал `403` на запросы через туннель.

## 2026-10-31 — Спайк аудио: фон работает

Проверено на iPhone в Телеграме: музыка играет в свёрнутом приложении и на локскрине, карточка с обложкой есть, переключение трека и **перемотка** с локскрина работают.

Перемотка сначала «не работала» — потому что в спайке не был зарегистрирован обработчик `seekto`. После добавления всё поехало. Урок: не объявлять ограничение платформы, пока не реализованы все обработчики Media Session.

Следствия:
- гибридная схема «отправить трек в чат» **не нужна**, `requestBackgroundFallback()` остаётся заглушкой;
- перемотка — только в нашем интерфейсе (кассета, кадр релиза);
- время в UI берём из `audio.currentTime` через rAF, а не из `timeupdate`.

Подробно: `docs/design/audio-findings.md`.

## 2026-10-31 — Аудио-движок

**`seekto`, `seekbackward` и `seekforward` не регистрируем.** Если их зарегистрировать, iOS заменяет кнопки «предыдущий / следующий трек» на локскрине кнопками ±15 секунд. Нам важнее переключение треков (кассета, сторона B), а перемотка доступна ползунком.
Уточнение: сначала мы зарегистрировали `seekto` — ползунок на локскрине заработал, но кнопки переключения треков заменились на ±10 секунд. Наблюдение требует проверки на чистой сессии (возможен кеш клиента), но приоритет расставлен так: **переключение треков важнее системной перемотки**, потому что это сторона B кассеты, а перемотка есть в самом плеере.

Итог: в `mediaSession.ts` остались только `play`, `pause`, `previoustrack`, `nexttrack`. Перемотка — в интерфейсе приложения (линия на кассете, линейка в кадре релиза, тап по строке текста).
Статус: **принято и проверено на устройстве**. Рабочий режим — только `play`, `pause`, `previoustrack`, `nexttrack`. Перемотка системного ползунка при этом недоступна, зато кнопки переключения треков на месте.

**RAF-цикл работает постоянно.** Цикл `requestAnimationFrame` запускается в конструкторе и крутится даже на паузе и без трека — лишние кадры и расход батареи. Нужно запускать на `play`, останавливать на `pause` и при `dispose`.
Статус: **к исправлению** перед задачей 04.

**Обложка в Media Session — хардкод** (`/content/covers/vdps-2026.jpg`). Должна приходить из данных трека: у `Track` нет поля обложки, но есть `releaseId` — в задаче 04 каталог научится её отдавать, тогда передаём в `load()`.
Статус: **к исправлению** в задаче 04.

## 2026-10-31 — Плашка «tg: браузер» врала

После перевода SDK на ленивую загрузку плашка на `/spike` показывала «браузер» даже внутри Телеграма: статус вычислялся один раз при импорте модуля (`safeTelegram() !== null`), то есть до того, как SDK успевал загрузиться.

Исправлено: в `src/app/telegram.ts` добавлен реактивный статус (`loading | ready | browser`) на `useSyncExternalStore`, `initTelegram()` выставляет его после загрузки SDK, `SpikePage` читает через `useTelegramStatus()`.

Урок: любая проверка, зависящая от асинхронного SDK, должна быть реактивной. И: не диагностировать проблему по индикатору, который сам может врать.
