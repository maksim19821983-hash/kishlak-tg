# Как не сломать то, что уже работает

Правила дешёвые. Стоимость одной поломки на устройстве — час ночных правок и потерянное доверие к цифрам в интерфейсе.

## 1. Тест раньше кода

Любой баг начинается с **падающего теста**, который его воспроизводит. Только потом правка. Так уже поймали двойное переключение трека: тест упал (`expected 1, got 2`), и стало видно, что переключение происходит дважды.

Тест без падения до правки ничего не доказывает.

## 2. CI на каждый пуш

`.github/workflows/ci.yml` — на каждый пуш в `main` и на каждый pull request GitHub прогоняет:

- `tsc --noEmit`
- `vitest run`
- `npm run build`
- размер сборки и число файлов

Красный CI = не мержим. Это единственное правило, которое надо соблюдать без исключений.

## 3. Ветка на любую переделку

Небольшая правка — можно в `main`. Переделка больше двух файлов — ветка. Мы уже видели, почему: переписанный учёт прослушиваний лежал в ветке, пока не прошёл проверку.

## 4. Смоук на телефоне после деплоя

Пять пунктов, две минуты. Если хоть один красный — откат, не «починим потом»:

1. Открывается плеер, играет, кассета крутится.
2. Конец трека → включается следующий, ровно один.
3. Обложка в каталоге показывает ровно `N/M`, без перекосов.
4. Перезагрузка страницы → прогресс на месте.
5. Профиль и каталог открываются, тема переключается.

## 5. Данные — только факты

Правило из `docs/spec/listen-accounting.md`, и оно общее: если что-то можно вычислить — не храним. Счётчики расходятся с фактами, вычисляемые значения — нет.

## 6. Одна точка правды на UI

Один подписчик (`subscribeFan`), один источник (`derive.ts`). Если для одного и того же числа появляется второй путь — это будущий баг.

## 7. Откат — тоже инструмент

- Откатить merge: `git revert -m 1 <commit>`
- Вернуть файл: `git checkout <commit> -- src/...`
- Откатить деплой: залить предыдущий `dist` (держать одну рабочую сборку рядом: `dist-ok/`)

## 8. Дисциплина задачи

- Одна задача — одна ветка/сессия.
- После задачи: тесты, сборка, коммит с внятным сообщением.
- Если правка затрагивает очередь, учёт или конец трека — без нового теста её не принимаем.
- Всё, что отложено, живёт в `docs/design/backlog.md`, а не в голове.
