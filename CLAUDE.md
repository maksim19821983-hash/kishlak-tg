# Кишлак Player — контекст проекта

> Читай этот файл первым. Он главнее любых догадок: если задача противоречит ему — спроси, а не решай сам.
> Карта проекта и статусы: `docs/MAP.md`.
> Дизайн: `docs/design/system.md` и `docs/design/screens.md`. План фич: `docs/design/backlog.md`. Задачи: `docs/prompts/*.md`.

## 1. Что мы строим

Telegram Mini App — музыкальный плеер, который на первом этапе существует только для одного артиста: **Кишлак** (он же АПФС). Это не «каталог музыки», а **сцена**: одно приложение, один артист, весь его звук, оформленный как арт-объект.

После обкатки на лояльной аудитории продукт превращается в платформу для других артистов. Поэтому **модель данных артист-агностична с первого дня** (`artist`, `release`, `track`), а интерфейс этапа 1 говорит на языке одного артиста и его эстетики.

## 2. Что делает продукт

1. **Сцена — обложка.** Обложка задаёт полярность всего экрана: светлая → тёплая бумага и чёрные чернила, тёмная → чернота и кремовый текст. Плюс один цвет из обложки уходит в прогресс и текущую строку текста. Никакого фиксированного «тёмного приложения».
2. **Текст — часть плеера, а не вкладка.** LRC-караоке с автопрокруткой и подсветкой текущей строки, тап по строке — переход к моменту. На плеере текст живёт как вкладыш в конверте.
3. **Плеер — главный экран.** Приложение открывается кассетой, а не каталогом: навигация из трёх табов (`ПЛЕЕР`, `КАТАЛОГ`, `ПРОФИЛЬ`), у релиза в каталоге есть кнопка ▶. Музыка включается максимум в один тап.
4. **Предмет, а не интерфейс.** Плеер — кассета: катушки крутятся, лента наматывается, сторона переворачивается. Фан-слой — проявление обложек по прослушанному, статистика, титул, профиль из шапки главной. Подробности: `docs/design/variants.md`, `docs/spec/fan-layer.md`.

## 3. Стек и архитектура

- **React 19 + TypeScript (strict) + Vite**
- **Tailwind CSS 3.4** поверх CSS-переменных (`--accent`, `--bg-*`), кастомные токены — только в `tailwind.config.ts`
- **Zustand** для состояния плеера и очереди (никаких Redux, никаких Context-простыней)
- **Vitest** для парсера LRC и утилит темы
- Аудио — **один `<audio>` singleton** вне React-дерева (`src/audio/engine.ts`), UI только подписывается на его состояние
- Анимации — CSS-переходы + `framer-motion` только если без него нельзя; по умолчанию обходимся CSS
- Пакеты добавляем **только** после согласования. Никаких UI-китов (MUI, shadcn, Radix — не нужны), никаких плеер-библиотек, никаких иконочных паков на 10 МБ

### Структура

```
src/
  app/            # роуты, telegram.ts, применение полярности к <html>
  audio/          # port.ts, engine.ts, mediaSession.ts, queue.ts, store.ts
  features/
    player/       # кассета, транспорт, таб-бар плеера
    lyrics/       # парсер LRC, вкладыш
    catalog/      # каталог, кадр релиза, шапка
    polarity/     # анализ обложки, палитра, accent-text
    fan/          # проявление, статистика, титул, профиль
  ui/             # примитивы: Sleeve, Stamp, TapeStrip, Button, ...
  data/           # типы, репозитории (CatalogRepo, FanRepo), manifest
  styles/         # tokens.css, fonts.css, grain.css
docs/
```

Аудио — инфраструктура, а не UI-фича: всё, что связано со звуком, живёт в `src/audio/`. В `src/features/` — только то, что рисует интерфейс.

### Архитектурные границы (важно для будущего порта)

Проект стартует как Mini App под одного артиста, но должен пережить перенос в нативное приложение и расширение до полного каталога (`docs/strategy/platform.md`). Поэтому:

- **Telegram SDK — только в `src/app/telegram.ts`.** Ни один компонент не импортирует `window.Telegram` напрямую.
- **Аудио — только через интерфейс `AudioPort`** (`play`, `pause`, `seek`, `load`, `subscribe`). Реализация сегодня — `<audio>` + Media Session; нативная заменит её без правок UI.
- **Данные — только через репозитории** (`CatalogRepo` — каталог, `FanRepo` — прогресс и статистика). Никаких `fetch` внутри компонентов.
- **Никакого «единственного артиста» в коде**: роуты `artist/:id`, `release/:id`, статистика с `artistId`.
- **Токены — одним файлом**, без цветов и размеров, размазанных по компонентам.

## 4. Аудио: главный технический риск

Механизм: HTML5 `<audio>` + **Media Session API**. Задача первого дня — проверить, что звук не умирает, когда Телеграм свёрнут, а телефон заблокирован (см. `docs/prompts/02-audio-engine.md`).

Правила:
- `MediaSession` метаданные: `title`, `artist`, `artwork` (512×512), `setPositionState` на каждый `timeupdate` (не чаще 1 раза в секунду)
- Обработчики: только `play` / `pause` / `previoustrack` / `nexttrack`
- Никаких автоплеев без жеста пользователя

**Правила локскрина (проверено на устройстве 02.11.2026, ломается легко):**

- Аудиоэлемент **обязан быть в документе** (`document.body.appendChild`). Отвязанный `new Audio()` в WKWebView Телеграма не попадает в Now Playing, и iOS подменяет ⏮⏭ на ±10. Защищено тестом `src/audio/audioElement.test.ts`.
- **Никогда не регистрировать** `seekto`, `seekbackward`, `seekforward`. Любой объявленный seek переключает iOS на кнопки перемотки. В коде они явно снимаются через `null`; тест `src/audio/mediaSession.test.ts` это стережёт.
- Обработчики ставить **по одному в своём try/catch** и первыми — `previoustrack`/`nexttrack`: одно исключение в общем блоке оставляет систему без кнопок.
- Повторная регистрация на событие `play` допустима и помогает, если WKWebView потерял обработчики.

Если фоновое воспроизведение не работает — закладываем интерфейс фолбэка `requestBackgroundFallback()` (бот присылает трек файлом в чат), но **не реализуем** его, пока не подтверждена необходимость

## 5. LRC

- Формат: `[mm:ss.xx]текст`, несколько таймкодов на строку, тег `[offset:±ms]`, метаданные `[ti:]`, `[ar:]`
- Бонус: word-level в формате `[mm:ss.xx]<mm:ss.xx>слово <mm:ss.xx>слово` — если есть, подсвечиваем по словам
- Метки секций `[mm:ss.xx][Куплет]`, `[01:02.53][Припев]` — не текст, а метка: рендерим приглушённым mono-label, без подсветки
- Пустые строки — паузы, не выбрасываем
- Парсер — чистый модуль, покрыт тестами, не знает про React
- Трека нет в LRC — превью текста на кассете не показываем, вкладыш недоступен

## 6. Дизайн-правила (жёсткие)

- Только токены из `docs/design/system.md`. Новый цвет/размер — сначала в систему, потом в код
- Ровно два шрифта: **Unbounded** (заголовки, кнопки, имена) и **JetBrains Mono** (метки, цифры, текст песен, служебное)
- Две полярности: `paper` (`#EDE7DC` фон, `#131211` чернила) и `dark` (`#0B0B0C` фон, `#F1EDE6` текст). Выбор — по средней светлоте обложки. Все цвета — из `docs/design/system.md`
- Акцент — ровно один на экран, взятый из обложки, и только в прогрессе, штампах и текущей строке
- Запрещено: тени (кроме физического предмета — кассеты), `backdrop-blur` на больших площадях, градиентные кнопки, чистый белый `#FFF`, чистый чёрный `#000`, скругления вне шкалы, эмодзи в интерфейсе
- Мобильный first: 390×844, safe-area (`env(safe-area-inset-*)`), `100dvh`, тач-таргеты ≥ 44 px
- Уважать `prefers-reduced-motion`: гасим автопрокрутку текста и переходы темы

## 7. Telegram

- SDK — `telegram-web-app.js`, типы через `@types/telegram-web-app`
- Обязательно: `ready()`, `expand()`, `disableVerticalSwipes()`, `BackButton` на вложенных экранах, `HapticFeedback` на ключевые действия
- Тема: полярность задаёт обложка трека, а не `themeParams`. Светлую тему телефона игнорируем, но контраст текста проверяем всегда
- Deep link: `?startapp=track_<id>` — открытие конкретного трека (для шаринга)
- Платежи: Telegram Stars через бота, на клиенте только `openInvoice` / «открыть бота»

## 8. Definition of Done

Задача не считается сделанной, пока:

- [ ] `npm run build` и `npx tsc --noEmit` проходят без ошибок и без `any`
- [ ] Прокликано на телефоне в Телеграме (не только в браузере), iPhone + Android
- [ ] Есть состояния: загрузка, пусто, ошибка, оффлайн
- [ ] Все цвета, шрифты, отступы — из токенов
- [ ] В консоли нет ошибок и ворнингов
- [ ] Анимации отключаются при `prefers-reduced-motion`
- [ ] Тексты не обрезаны на длинных названиях (проверить трек с 40+ символами)

## 10. Дорожная карта

- **Фаза 0 — фундамент.** Репозиторий, токены, этот файл, спайк фонового аудио
- **Фаза 1 — плеер.** Аудио-движок, полный плеер, мини-плеер, очередь, шаффл/репит
- **Фаза 2 — полярность.** Определение `paper`/`dark` по светлоте обложки, акцент из обложки, переходы цвета
- **Фаза 3 — текст.** Парсер LRC, экран караоке, тап по строке
- **Фаза 4 — каталог.** Главная, страница артиста, релизы, плейлисты, поиск по каталогу
- **Фаза 5 — фан-слой.** Проявление обложек по доле прослушанных треков, статистика, титул, профиль из шапки главной (см. `docs/spec/fan-layer.md`)
- **Фаза 6 — Телеграм.** Шаринг трека, Stars, реф-ссылка, haptics, deep links
- **Фаза 7 — платформа.** Второй артист, онбординг, выбор артиста

## 11. Словарь

- **Полярность** — режим экрана: `paper` (бумага) или `dark` (чернота), выбирается по светлоте обложки
- **Кассета** — плеер как физический предмет: катушки, лента, сторона A/B
- **Вкладыш** — текст песни и трек-лист как бумажная вкладка в конверте
- **Титул** — одна фраза о том, как ты слушаешь артиста («РЕЗИДЕНТ», «НОЧНАЯ СМЕНА»)
- **Профиль** — экран со статистикой и титулом; отдельный таб рядом с плеером и каталогом
- **Релиз** — альбом, EP или сингл
